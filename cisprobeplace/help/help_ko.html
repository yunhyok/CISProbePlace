 1. 한눈에 보기

probe를 놓을 좌표를 CSV · XLSX 표나 Sigrity SPD 파일의 DUT 핀에서 읽어, Ansys Electronics Desktop(AEDT)의 HFSS에서 실행할 script 파일을 만들어 주는 프로그램입니다. 만들어진 script를 HFSS에서 실행하면, 미리 준비해 둔 원본 probe가 좌표마다 자동으로 복제 · 회전 · 이동됩니다.

그림 1. 전체 작업 흐름. 이 프로그램은 HFSS에 직접 연결하지 않고 script 파일만 만듭니다.

 2. 빠른 시작

  1. HFSS에서 원본 probe의 object를 group에 넣을 것. 한 종류는 Source_Group, 자동 긴 · 짧은 판정은 LongProbe · ShortProbe 준비. 실제 사용할 이름은 Pin editing과 표의 SOURCE_GROUP에서 확인할 것.
  2. 좌표 파일을 준비합니다. 표를 만들 때는 첫 행에 X좌표, Y좌표, Net Name을 적고 그 아래에 좌표를 한 행에 하나씩 적습니다. DUT가 들어 있는 SPD 파일도 사용할 수 있습니다.
  3. AEDT target 탭에 HFSS의 Project 이름과 Design 이름을 입력합니다.
  4. Input and filters 탭의 Browse Coordinate File로 파일을 고르고 Load Inputs를 누릅니다. SPD는 이어서 DUT 부품과 site 번호를 선택합니다.
  5. 흰색 핀맵에서 핀 위치를 확인합니다. 색은 SOURCE_GROUP, 삼각형은 Tips point 설정에 따른 예상 팁 방향입니다. Pin editing에서 제품의 팁 방향을 선택할 것. 방향 전환은 즉시 반영됩니다. 물리적인 SIDE는 표와 툴팁에서 확인할 것. 핀을 누르면 표에서도 해당 핀을 확인할 수 있습니다.
  6. Generate AEDT Script를 눌러 script(.py)를 저장합니다.
  7. AEDT에서 해당 project와 design을 연 상태로, AEDT의 Run Script 기능으로 저장한 파일을 실행합니다.

가장 간단한 좌표 파일(CSV)은 다음과 같습니다.

X좌표,Y좌표,Net Name
10,5,SIGNAL_A
5,10,SIGNAL_B
0,5,DGND

 3. 입력 파일 양식

입력 파일은 하나입니다. 다음 세 가지 양식을 읽을 수 있습니다. CSV · XLSX 파일은 header(열 이름) 행을 보고 양식 A와 B 가운데 하나로 자동 판별하고, 확장자가 .spd인 파일은 양식 C로 읽습니다.

양식언제 쓰는가
A. 좌표 파일 (권장)probe 좌표만 직접 정리한 파일. 열 3개(선택 열 포함 4개)면 충분합니다.
B. Allegro symbol pin reportAllegro에서 내보낸 pin report를 그대로 쓰는 경우. 기존 양식과의 호환용입니다.
C. Sigrity SPDSigrity의 텍스트 SPD 파일에서 DUT 부품의 핀 좌표를 바로 가져오는 경우. 부품과 site를 골라서 읽습니다. (3.8)

3.1 표 양식 A · B의 공통 규칙

항목규칙
파일 형식확장자가 .csv 또는 .xlsx인 파일만 읽습니다. .xls, .xlsm, .txt 파일은 Excel의 "다른 이름으로 저장"으로 .xlsx나 CSV로 바꾸어 주십시오.
XLSX의 시트파일을 마지막으로 저장할 때 선택되어 있던 시트 하나만 읽습니다. 좌표가 있는 시트를 선택한 상태에서 저장하십시오.
XLSX의 수식수식이 든 cell은 Excel이 마지막으로 계산해 저장해 둔 결과 값을 읽습니다. Excel에서 열어 저장한 파일이면 문제가 없습니다.
CSV 구분 기호쉼표(,)입니다. 값 안에 쉼표가 들어가면 그 값을 큰따옴표로 감쌉니다.
CSV 문자 인코딩UTF-8(BOM이 있어도 됨) 또는 CP949(한글 Windows Excel의 "CSV (쉼표로 분리)")를 읽습니다.
header 행의 위치첫 행이 아니어도 됩니다. 위에서부터 찾아 필수 열 이름이 모두 들어 있는 첫 번째 행을 header로 씁니다. 그 위에 있는 제목 · 날짜 같은 행은 무시합니다.
header 이름대문자와 소문자를 구분하지 않고, 앞뒤 공백도 무시합니다. 그 밖의 철자는 표에 적힌 이름과 같아야 합니다. (예: Net Name과 NET_NAME은 인정되지만 NetName은 인정되지 않습니다.)
열의 순서 · 추가 열열 순서는 자유입니다. 필요 없는 다른 열이 함께 있어도 되며, 그런 열은 읽지 않습니다.
데이터 행header 행 아래의 모든 행을 읽습니다. 완전히 비어 있는 행은 건너뜁니다.
좌표 값숫자만 적습니다. 단위는 mm로 사용됩니다. 소수점은 마침표이고 1.5e-3 같은 지수 표기도 됩니다.
다음은 오류가 됩니다: 빈 칸, 단위가 붙은 값(1.5mm), 천 단위 쉼표(1,234.5), NaN · inf.
Net 이름비워 두어도 됩니다. 이름이 없는 net은 화면의 NET 목록에 (blank)로 표시됩니다.

Source_probe name 열의 규칙

  • 적은 글자가 그대로 HFSS group 이름이 됩니다. 접두어를 붙이거나 글자를 바꾸지 않으므로, HFSS에 만들어 둔 group 이름과 대문자 · 소문자까지 똑같이 적으십시오. (앞뒤 공백만 제거됩니다.)
  • 열이 없거나 값이 빈 핀은 기본적으로 Source_Group을 사용합니다. 두 본딩 열의 지그재그가 확인된 핀에는 7.3절의 긴 · 짧은 그룹이 자동으로 적용됩니다.

header가 없는 Source_probe 열

Source_probe name이라는 header가 없더라도, 필수 열 가운데 가장 오른쪽 열의 바로 오른쪽 열에 header는 비어 있고 값만 적혀 있으면 그 열을 Source_probe name으로 읽습니다.

 ABCD
1PIN_XPIN_YNET_NAME(비어 있음)
244.004442.9169U1_VNTGSource_CLS35SE_SBP
343.904542.1669DGNDSource_CLS35S_SBP
주의. 이 규칙 때문에, 그 위치의 열에 메모나 다른 값을 header 없이 적어 두면 HFSS group 이름으로 읽힙니다. 관계없는 내용은 header를 붙이거나 다른 열에 적으십시오.

생성되는 object의 번호

양식 A에서는 데이터 행의 순서(빈 행은 세지 않음)가 1, 2, 3 … 번호가 되고, 이 번호가 HFSS에 만들어지는 object 이름의 앞부분에 쓰입니다. (8. 이름 규칙 참고)

3.5 자동 좌표 중심 보정

파일을 불러오면 프로그램이 모든 좌표를 평행 이동시켜, 좌표 전체를 둘러싼 사각형(bounding box)의 중심이 원점 (0, 0)에 오도록 맞춥니다. 좌표가 원점에서 아주 멀리 떨어져 있어도 따로 손볼 필요가 없습니다.

그림 2. X 범위가 1000~1020, Y 범위가 2000~2060이면 중심 (1010, 2030)을 모든 좌표에서 뺍니다.

  • 중심은 CSV · XLSX에서는 파일에 들어 있는 모든 행으로, SPD에서는 선택한 부품과 site의 모든 핀으로 계산합니다. 그 뒤에 화면에서 net이나 범위로 일부만 선택해도 중심은 달라지지 않습니다.
  • 미리보기 표, X · Y 범위, 핀맵, 생성되는 script의 좌표는 모두 보정된 좌표입니다. 따라서 probe는 HFSS의 원점을 중심으로 배치됩니다.
  • 입력 파일은 읽기만 하며 수정하지 않습니다.

3.6 입력 오류 메시지와 해결 방법

파일을 읽지 못하면 대화 상자와 화면 아래 Log에 Input error: …가 표시됩니다. 메시지의 row N은 파일에서의 실제 행 번호(Excel의 행 번호)입니다. SPD 파일의 오류 메시지는 3.8에 따로 정리되어 있습니다.

메시지원인과 해결 방법
Unsupported file format for … Use .csv or .xlsx.확장자가 .csv, .xlsx, .spd 가운데 어느 것도 아닙니다. 표는 Excel에서 .xlsx나 CSV로 다시 저장하십시오.
Could not find required header. …필수 열 이름이 한 행에 모두 있지 않습니다. header 철자, 필수 열 3개(X · Y · Net)가 같은 행에 있는지, XLSX라면 좌표가 있는 시트를 선택한 채 저장했는지 확인하십시오.
Missing X좌표 at row N.

Could not decode CSV file …CSV의 문자 인코딩을 읽지 못했습니다. Excel에서 "CSV UTF-8 (쉼표로 분리)"로 다시 저장하십시오.

3.7 CSV · XLSX 입력 점검표

  • 확장자가 .csv 또는 .xlsx인가?
  • header에 X · Y · Net 열 이름이 정확한 철자로, 한 행에 모두 있는가?
  • 좌표 칸에 숫자만 들어 있는가? (단위 · 쉼표 · 빈 칸 없음)
  • 좌표의 단위가 mm인가?
  • Source_probe name에 적은 이름이 HFSS group 이름과 똑같은가?
  • XLSX라면 좌표가 있는 시트를 선택한 상태로 저장했는가?

3.8 양식 C — Sigrity SPD

Sigrity의 텍스트 SPD 파일에 들어 있는 부품 핀의 좌표와 net 이름을 그대로 가져옵니다. 좌표 표를 따로 만들 필요가 없고, 한 파일에 여러 site가 들어 있으면 원하는 부품과 site만 골라서 읽습니다.

파일에서 읽는 내용

프로그램은 SPD 파일에서 부품의 핀 연결과 그 핀이 놓인 Node의 좌표만 읽습니다. 도형 · 배선 · via 같은 나머지 내용은 읽지 않습니다.

.Package $Package
Node101!!A1::CLK/3 X = 1250um Y = 400um Layer = TOP PadStack = PAD80  ← ③
Node102!!A2::DGND X = 1.25mm Y = 0.9mm Layer = TOP PadStack = PAD80
.EndPackage
.Connect SITE3 DUT  ← ①
A1 $Package.Node101!!A1::CLK/3  ← ②
A2 $Package.Node102!!A2::DGND
.EndC
순서읽는 줄가져오는 것
①.Connect <인스턴스> <부품>인스턴스 이름(SITE3)과 부품 이름(DUT). 이 줄부터 .EndC처럼 .으로 시작하는 다음 줄까지가 그 인스턴스의 핀입니다. 부품 이름이 같은 인스턴스들은 선택 창에서 한 부품으로 묶입니다.
②<핀> $Package.Node…핀 이름(A1)과, 그 핀의 좌표가 적혀 있는 Node의 이름(Node101)
③Node…!!<핀>::<net> X = … Y = …그 Node의 X · Y 좌표와 net 이름(CLK/3). net 이름이 Node 줄에 없으면 ②의 줄에 적힌 이름을 씁니다.

SPD 파일이 지켜야 할 점

항목규칙
파일 형식확장자가 .spd인 텍스트 파일이어야 합니다. 문자 인코딩은 UTF-8 또는 CP949를 읽습니다. 바이너리 파일이나 UTF-16으로 저장된 파일은 읽지 못합니다.
좌표의 단위X · Y 값에는 단위가 붙어 있어야 합니다. nm, um(µm), mm, cm, m, mil, in(inch)를 읽어 모두 mm로 바꿉니다. 단위가 없는 값(X = 1.25)은 길이를 알 수 없으므로 오류가 됩니다.
Node의 위치핀이 가리키는 Node 줄은 파일의 .EndPackage 줄보다 앞에 있어야 합니다.
줄 이어 쓰기Node 줄 바로 다음에 +로 시작하는 줄이 있으면 앞 줄에 이어진 내용으로 읽습니다.
주석*로 시작하는 줄은 읽지 않습니다. 핀 연결 줄 앞에 *를 붙이면 그 핀은 가져오지 않습니다.
대문자 · 소문자.Connect, Node, $Package 같은 예약어와 단위는 대소문자를 구분하지 않습니다. 인스턴스 · 부품 · 핀 · net 이름은 파일에 적힌 그대로 씁니다.

불러오는 순서

그림 3. 왼쪽은 부품과 site를 고르는 창, 오른쪽은 선택을 마친 뒤의 Input Files 영역입니다.

  1. Browse Coordinate File에서 .spd 파일을 고르고 Load Inputs를 누릅니다. 파일이 크면 읽는 데 시간이 걸릴 수 있습니다.
  2. 읽기가 끝나면 선택 창이 열립니다. DUT component(①)에서 부품을, Site(②)에서 site를 고르고 OK를 누릅니다.
  3. 핀맵과 미리보기 표에 그 부품 · site의 핀이 나타납니다. X · Y 좌표(mm)와 원래 net 이름을 확인할 것. 현재 선택은 Input Files 영역(③)에 표시됩니다.
  4. 다른 부품이나 site로 바꾸려면 Change DUT / site(④)를 누릅니다. 파일을 다시 읽지 않으므로 바로 바뀝니다.
선택 창의 항목목록의 내용과 처음 선택되는 값
① DUT component파일에 들어 있는 모든 부품 이름입니다. 이름이 DUT이거나 DUT 바로 뒤에 숫자 · _ · . · -가 오는 부품(DUT1, DUT_A 등)이 있으면 그것이 처음에 선택되고, 없으면 목록의 첫 부품이 선택됩니다.
② Site고른 부품에 들어 있는 site 번호가 작은 순서로 나오고, 번호가 없는 핀이 있으면 맨 끝에 (unassigned)가 나옵니다. 처음에는 가장 작은 번호가 선택됩니다. (0번이 있으면 0번, 없으면 1번 …)

선택 창에서 Cancel을 누르면 아무것도 바뀌지 않습니다. 새 파일을 불러오던 중이었다면 불러오기가 취소되고 이전 입력이 그대로 남습니다.

site를 정하는 규칙

그림 4. site는 인스턴스 이름에서 먼저 찾고, 없으면 핀마다 net 이름에서 찾습니다.

핀마다 아래 순서로 이름을 살펴보고, 처음 찾은 번호를 그 핀의 site로 정합니다.

순서살펴보는 이름site 번호로 인정하는 표기예
1인스턴스 이름이름 전체가 SITE<번호>이거나, /<번호>로 끝남SITE3, U2/3 → 3
2net 이름/<번호>로 끝나거나, U<번호>_로 시작함CLK/3, U3_CLK → 3
3핀 이름2번과 같음A1/3 → 3
4Node 줄에 적힌 핀 이름2번과 같음 
—어디에서도 찾지 못함(unassigned)로 묶입니다.
  • 인스턴스 이름에 번호가 있으면 그 인스턴스의 핀은 net 이름과 관계없이 모두 그 site에 들어갑니다. DGND 같은 공통 net의 핀도 포함됩니다.
  • 번호는 숫자로만 이루어져야 합니다. VDD/1V8이나 CLK/3A는 site 표기로 보지 않습니다. CLK/007은 7번입니다.
  • 표기의 대문자 · 소문자는 구분하지 않습니다. (site3, u3_clk)
  • 인스턴스 이름에서는 U<번호>_ 표기를 site로 보지 않습니다. (U1_0은 site가 없는 인스턴스입니다.)
주의. (unassigned)는 번호가 있는 site와 따로 선택하는 항목입니다. 인스턴스 하나에 여러 site가 섞여 있는 파일(그림 4의 나)에서는 DGND처럼 site 표기가 없는 공통 net의 핀이 (unassigned)에만 나타나므로, 번호가 있는 site를 골랐을 때는 그 핀들이 포함되지 않습니다. 또한 좌표의 중심은 선택마다 따로 맞추므로, 두 선택에서 만든 script를 그대로 겹쳐 쓸 수는 없습니다.

script는 probe를 새로 그리지 않고, HFSS design에 미리 만들어 둔 원본 probe를 복제합니다. 원본은 group에 넣어 두어야 하며, 어느 group을 복제할지는 입력 파일의 각 행이 정합니다.

4.2 group을 만들 때 지킬 점

  • group 안에는 그 probe를 이루는 모든 object(solid와 sheet)를 넣습니다. group 안의 object가 하나씩 모두 복제됩니다.
  • group은 비어 있으면 안 됩니다. 필요한 group이 없거나 비어 있으면 script는 아무것도 배치하지 않고 오류 메시지를 낸 뒤 멈춥니다.
  • net 이름이 DGND인 좌표에서는, 복제된 object 가운데 sheet object에 Perfect E boundary가 자동으로 부여됩니다. (dgnd처럼 소문자로 적어도 같습니다.)
  • script를 실행하면 object가 많이 만들어집니다. 실행하기 전에 project를 저장해 두면 되돌리기 쉽습니다.

4.3 원본 probe의 위치와 방향

script는 원본을 원점을 지나는 Z축 기준으로 회전 복제한 다음 입력 좌표 (X, Y)만큼 이동합니다. 그러므로 원본은 다음과 같이 놓아 두어야 합니다.

그림 6. 좌표 하나에 probe가 놓이는 과정.

  • 긴 프로브와 짧은 프로브 모두 본딩 기준점을 HFSS의 원점 (0, 0)에 맞출 것. script는 각 원본 모델의 본딩 기준점을 입력한 X · Y 위치에 배치합니다.
  • 방향: right side(X가 가장 큰 쪽 변)에 놓였을 때의 방향으로 그려 둡니다. 기본 설정에서 right의 회전각이 0°이기 때문입니다. 다른 방향으로 그렸다면 화면의 회전각을 조정합니다. (7.2)

 6. 사용 순서 상세

6.1 대상과 회전각 지정 — ④ AEDT target

  • Project, Design: HFSS에 있는 이름과 똑같이 입력합니다. script는 이 이름의 project와 design을 활성화한 뒤 작업하므로, 실행할 때 그 project가 AEDT에 열려 있어야 합니다. 칸을 비우면 Project1, HFSSDesign1이 쓰입니다.
  • Right / Top / Left / Bottom rotation: side별 회전각(도)입니다. 보통은 기본값을 그대로 둡니다. (7.2)

6.2 파일 불러오기 — ①

  1. Browse Coordinate File을 눌러 CSV, XLSX 또는 SPD 파일을 고릅니다.
  2. Load Inputs를 누릅니다. SPD 파일이면 부품과 site를 고르는 창이 열립니다. (3.8) 성공하면 Log에 Input load complete: N pin rows.가 표시됩니다.
  • 불러온 직후에는 모든 net이 체크되고 범위가 전체로 설정되어, 가져온 좌표가 모두 선택된 상태가 됩니다.
  • 파일 내용을 고쳤으면 Load Inputs를 다시 눌러야 반영됩니다.
  • 파일을 다시 읽거나 DUT · site를 바꾸면 핀별 그룹과 방향 설정이 초기화됩니다.
  • 불러오기에 실패하거나 SPD 선택 창에서 Cancel을 누르면, 이전에 불러온 입력이 그대로 유지되고 파일 칸도 그 파일로 돌아갑니다. 아직 불러온 입력이 없을 때는 고른 파일이 파일 칸에 남으므로, 파일을 고친 뒤 Load Inputs만 다시 누르면 됩니다.

6.5 핀별 그룹 · 방향 지정 — ④ Pin editing

입력 파일을 고치지 않고 일부 좌표의 HFSS group만 바꾸고 싶을 때 씁니다. HFSS group 칸에 group 이름을 입력한 뒤 버튼을 누릅니다.

버튼동작
Apply to picked pins표나 핀맵에서 직접 고른 핀에 그룹 이름을 적용합니다. 예를 들어 긴 probe를 쓸 핀만 고른 뒤 LongProbe를 지정합니다.
Apply to filtered pinsnet · 범위 필터를 통과한 모든 핀에 그룹을 적용합니다.
Clear group overrides직접 지정한 핀별 그룹만 모두 해제. 현재 자동 판정 설정과 입력 그룹의 우선순위에 따라 그룹을 다시 적용하며, 핀별 SIDE 지정은 유지.

그룹 편집은 표, 핀맵, 생성할 script에 함께 반영됩니다. 직접 지정한 그룹과 방향은 현재 불러온 파일 · site에서 사용합니다. 원본 파일에 기록되지 않습니다.

그룹 우선순위: 직접 지정한 핀별 그룹 → 입력 파일의 그룹 → 자동 긴 · 짧은 그룹 → 기본 그룹. Automatic probe groups가 켜져 있고 Replace input groups도 선택하면, 판정 가능한 핀의 자동 그룹이 입력 그룹보다 우선합니다. 직접 지정한 핀별 그룹은 항상 우선합니다. 미판정 핀은 입력 그룹 또는 Source_Group 등 기존 기본 그룹 유지.

Apply CIS side는 직접 고른 핀의 방향에 적용. Auto를 적용하면 전체 입력에서 계산한 자동 SIDE로 복귀. 자동 SIDE와 다른 방향을 직접 지정한 핀은 긴 · 짧은 판정이 Undetermined가 되며 자동 그룹 적용 대상에서 제외됩니다.

6.6 script 만들기와 실행 — ⑤

  1. 기본 배치 대상은 net · 좌표 범위 등 필터를 통과한 모든 핀입니다. 직접 고른 핀만 배치하려면 Place picked pins only를 선택하고 핀 개수를 확인할 것.
  2. Generate AEDT Script를 누르고 저장할 위치와 파일 이름을 정합니다.
  3. Log에서 Side summary(side별 좌표 수)와 Source group summary(group별 좌표 수)를 확인합니다.
  4. AEDT에서 대상 project와 design을 열고, AEDT의 Run Script 기능으로 저장한 파일을 실행합니다.
참고. 선택을 바꾼 직후에는 선택 결과가 갱신되는 동안 Load Inputs와 Generate AEDT Script 버튼이 잠깐 비활성화됩니다. 갱신이 끝나면 다시 누를 수 있습니다.

 7. CIS side 인식과 회전각

probe는 놓이는 변(side)에 따라 방향이 달라야 하므로, 프로그램이 좌표마다 side를 판별하고 side별 회전각을 적용합니다.

그림 8. 네 변의 SIDE와 예상 팁 방향. 그림의 삼각형은 Toward center 예시이며, HFSS 회전 변수와는 별도.

7.1 side를 정하는 규칙

  1. 불러온 좌표 전체를 둘러싼 사각형과 핀 배열로 판별합니다. SPD에서는 선택한 DUT와 site 전체가 기준입니다.
  2. 지원되는 지그재그 본딩 두 열과 안쪽 방향을 뒷받침하는 다른 변이 확인되면, 해당 핀은 본딩 열의 SIDE가 아래 기본 규칙보다 우선합니다. 가로 · 세로 열이 모서리에서 겹쳐 모호한 핀은 자동 긴 · 짧은 판정을 보류하고 아래 기본 SIDE 유지. (7.3)
  3. 본딩 열로 확인되지 않은 핀에는 다음 기본 규칙을 적용합니다. X 값이 같은 좌표가 2개 이상이면 세로 줄, Y 값이 같은 좌표가 2개 이상이면 가로 줄로 봅니다. (0.000001 mm 이내의 차이는 같은 값으로 봅니다.)
  4. 줄이 기준 사각형의 바깥쪽 30% 띠 안에 있으면 변으로 인정합니다. 왼쪽 띠의 세로 줄은 left, 오른쪽 띠의 세로 줄은 right, 위쪽 띠의 가로 줄은 top, 아래쪽 띠의 가로 줄은 bottom입니다.
  5. 좌표가 그런 줄 하나 위에 있으면 그 줄의 side가 됩니다.
  6. 좌표가 가로 줄과 세로 줄 둘 다 위에 있으면 좌표가 더 많이 놓인 줄의 side가 됩니다. 개수가 같으면 더 가까운 바깥 변, 그래도 같으면 right → top → left → bottom 순서로 정합니다.
  7. 어느 줄 위에도 없는 좌표는 가장 가까운 바깥 변의 side가 됩니다. 거리가 같으면 right → top → left → bottom 순서입니다. 인정된 줄이 전체에 하나뿐이거나 없을 때도 모든 좌표를 이 방식으로 정합니다.
  8. 불러온 배열 전체가 가로 한 줄이면 자동값은 top, 세로 한 줄이면 right입니다.
왼쪽 변의 핀 하나만 골라도 그 핀에는 CISRotAng_Left가 적용됩니다. 모서리 핀의 실제 방향이 자동 판정과 다르면 핀을 고른 뒤 CIS side에서 올바른 변을 적용할 것. Auto를 적용하면 해당 핀의 자동 판정값으로 복귀합니다.

7.2 회전각

sideHFSS design 변수기본값화면의 입력 칸
rightCISRotAng_Right0°Right rotation
topCISRotAng_Top270°Top rotation
leftCISRotAng_Left180°Left rotation
bottomCISRotAng_Bottom90°Bottom rotation
  • script는 실행될 때 이 네 변수를 HFSS design 변수로 만들고(이미 있으면 값을 고치고), 회전 복제의 각도로 변수 이름을 사용합니다. 값은 HFSS의 design 변수 목록에서 확인할 수 있습니다.
  • 기본값은 원본을 right side 방향으로 그려 두었다고 보고, right → bottom → left → top 순서로 90°씩 커지도록 정해져 있습니다.
  • 원본을 다른 방향으로 그렸거나 배치된 probe의 방향이 기대와 다르면, 해당 side의 값을 바꾼 뒤 script를 다시 만듭니다. 위아래가 서로 바뀌어 보인다면 Top과 Bottom의 값을 맞바꾸면 됩니다(Top 90, Bottom 270).
처음 사용할 때. 회전 방향은 모델을 보는 방향에 따라 다르게 보일 수 있습니다. 먼저 네 변에서 좌표를 몇 개씩만 골라 script를 만들어 실행해 보고, probe가 원하는 방향을 향하는지 확인한 다음 전체를 배치하십시오.

7.3 지그재그 본딩 열에서 긴 · 짧은 프로브 구분

입력 X · Y는 각 프로브의 본딩 위치입니다. 변을 따라 핀이 바깥 열과 안쪽 열에 번갈아 놓이고 팁이 한 줄에 정렬된다면, 팁 정렬선까지 거리가 더 먼 열에 긴 프로브가 필요합니다.

위쪽 변 평면 개념도. 사각형은 본딩 위치, 원은 팁. 선은 두 열에서 팁까지의 상대 거리를 나타냅니다.

제품의 팁 방향바깥 본딩 열안쪽 본딩 열
중심 쪽 (Toward center)긴 프로브짧은 프로브
바깥쪽 (Toward outside)짧은 프로브긴 프로브
  1. Pin editing → Tips point에서 제품의 팁 방향을 선택할 것. 전환은 즉시 반영되며 같은 핀의 SIDE는 유지됩니다. 긴 · 짧은 판정, 자동 그룹, 핀맵의 예상 팁 방향이 함께 전환됩니다. HFSS 회전각은 바뀌지 않으며 AEDT target의 값이 적용됩니다.
  2. 긴 · 짧은 그룹 이름을 HFSS에 준비한 원본 그룹 이름과 맞출 것. 기본은 LongProbe와 ShortProbe. 그룹 이름을 수정했으면 Apply inference로 검사 · 확정할 것.
  3. Probe type (filtered)의 Long · Short · Undetermined 개수를 확인할 것. 핀맵이나 표의 핀에 마우스를 올리면 Predicted probe 툴팁으로 종류 확인 가능. 한 줄, 지원 방향이 없는 단독 변, 핀이 적은 열, 모호한 모서리 등은 미판정으로 유지하며 직접 그룹 지정 가능.

4변 · 3변 · 2변의 X/Y축 정렬 배열에서 각 변의 지그재그를 검사합니다. 기본 판정에는 번갈아 배치된 두 열 각각 최소 4개 핀과 안쪽 방향을 뒷받침하는 다른 변이 필요합니다. 규칙적인 격자는 판정에서 제외하지만, 불규칙한 배열이 본딩 열과 같은 모양이면 좌표만으로 구별하지 못할 수 있습니다. 기울어진 배열이나 모서리의 겹치는 열도 직접 확인할 것. 분류 결과는 상대적인 프로브 종류이며, 실제 길이와 팁 정렬선 위치는 제품 설계값을 사용할 것.

 8. 생성되는 script가 하는 일

저장되는 파일은 AEDT에 내장된 IronPython으로 실행하는 script입니다. 실행하면 다음 순서로 동작합니다.

  1. 입력한 이름의 project와 design을 활성화합니다.
  2. 회전각 design 변수 4개를 만들거나 값을 갱신합니다.
  3. 필요한 source group이 모두 있고 비어 있지 않은지 검사합니다. 하나라도 문제가 있으면 여기서 멈춥니다.
  4. 좌표마다, 그 좌표의 source group에 든 object 하나하나에 대해 다음을 수행합니다.
    • 그 좌표의 side 변수 각도로 Z축 기준 회전 복제
    • 복제된 object의 이름 변경 (아래 이름 규칙)
    • Group 속성을 Generated_Group으로 지정
    • 좌표 (X, Y)만큼 이동
  5. net 이름이 DGND인 좌표는 복제된 sheet object에 Perfect E boundary를 부여합니다.
  6. 마지막으로, 선택된 좌표 전체를 덮는 사각형 sheet 2장을 만들고 Perfect E boundary를 부여합니다.

이름 규칙

만들어지는 것이름
복제된 probe object<번호>_<Net 이름>_<원본 object 이름>
번호는 양식 A에서는 행 순서, 양식 B에서는 PIN_NUMBER, 양식 C(SPD)에서는 핀 이름입니다.
DGND 좌표의 boundaryPerfE_<번호>_<Net 이름>

크기는 선택된 좌표 범위의 폭 · 높이의 1.1배입니다. 폭이나 높이가 0이면 그 방향은 1 mm로 만듭니다.
사각형 sheet의 boundaryPerfE_Placement_Bounds
  • 이름에 쓸 수 없는 문자(영문자 · 숫자 · 밑줄 이외)는 밑줄로 바뀝니다. 예: 3번 좌표, net NET/A, 원본 Tip → 3_NET_A_Tip
  • 같은 이름이 design에 이미 있으면 뒤에 _2, _3 …이 붙습니다. 그래서 같은 script를 두 번 실행하면 probe가 한 벌 더 만들어집니다.

 10. 알아 둘 점

  • CSV · XLSX의 좌표는 mm 값으로 읽습니다. SPD의 좌표는 파일에 적힌 단위를 mm로 바꾸어 씁니다.
  • 프로그램은 입력 파일을 읽기만 하며 고치지 않습니다.
  • 프로그램은 HFSS에 직접 연결하지 않습니다. 배치는 저장된 script를 AEDT에서 실행할 때 이루어집니다.
  • script는 AEDT 안에서 실행하는 IronPython용입니다. 일반 Python으로는 실행되지 않습니다.
  • 핀별 그룹과 방향 설정은 생성한 script에 반영되며, 원본 좌표 파일에는 기록되지 않습니다.
